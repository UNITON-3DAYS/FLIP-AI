# FLIP 시스템 아키텍처 / 제품 방향

인식·채점 부분의 시스템 경계와 콘텐츠 트랙 정리.
(인식 모델·학습 세부는 [recognition-pipeline.md](recognition-pipeline.md) 참고.)

---

## 1. 시스템 경계

책 넘김 캡처와 장(page) 분리는 **다른 서버**가 담당한다. 우리는 **페이지 이미지 1장을 입력으로 받는 데서 시작**한다.

```
[다른 서버]  넘김 영상 → 장별 분리 → 페이지 이미지들
                                        │
                                        ▼
[우리]  페이지 이미지 → 정렬 → 답공간 크롭 → YOLO → 채점 결과
```

| | 담당 |
|---|---|
| 넘김 영상, 모션 감지, 장별 분리 | ❌ 다른 서버 |
| 페이지 이미지 받아 인식·채점 | ✅ 우리 |

→ **모션 감지/자동촬영은 우리 스코프 아님.** 우리 서비스 = **"페이지 이미지 in → 채점 결과 out".**

---

## 2. 콘텐츠 트랙 (2종)

인식(YOLO)은 공통 재사용. **"답칸을 어떻게 찾느냐(앞단)"만** 트랙별로 다르다.

| 트랙 | 설명 | 답칸 찾기 | 난이도 |
|---|---|---|---|
| **자체 시험지** | 우리가 만듦 (레이아웃 통제 가능) | **ArUco 마커 + 고정좌표 슬라이싱** | 쉬움 |
| **쎈 등 기성 학습지** | 기성 출판물 (통제 불가, 표준화됨) | **페이지 사전등록 + 페이지 인식 + 정렬 + 등록좌표 크롭** | 중 |

### 쎈이 가능한 이유
- 쎈은 **표준 출판물** → 판(edition)별 **페이지 레이아웃을 한 번 등록**하면 모든 학생 책에 동일 적용.
- 마커가 없지만 **인쇄된 문제 자체가 정렬 기준**(feature matching).
- **전제: 학생은 풀이를 섞지 않고, 문제 밑 공간에 답만 적는다.** → 답공간에 손글씨가 답 하나뿐이라 인식이 깨끗. (풀이 섞이면 "지옥 케이스" = VLM 영역, 지금 범위 밖)

---

## 3. 우리 파이프라인 (입력 = 페이지 1장)

```
페이지 이미지
  → (쎈이면) 어느 페이지인지 인식 + 정렬 (homography)
  → 답공간 좌표로 크롭  (자체=마커좌표 / 쎈=등록좌표)
  → 각 크롭 YOLO-det → 답 문자열
  → 정답 키 비교 → O/X
  → confidence 낮은 것만 사람 확인
```

- **인식(YOLO)** = 공통. 이미 구현·검증됨.
- **앞단(정렬·크롭)** = 트랙별로 다름. 미구현.

---

## 4. Staging (구현 순서)

1. **자체 시험지** — 우리가 통제 → 마커+좌표 크롭. **"사진→크롭→YOLO→채점" 전체 루프 완성.** 데모용.
2. **쎈** — 페이지 등록 도구 + 인식 + 정렬 얹기. 인식기는 그대로 재사용.
3. (책 넘김 캡처는 다른 서버, 우리 스코프 밖)

각 단계가 앞 단계를 재사용 → 리스크 낮음.

---

## 5. 열린 질문

- **페이지 ID를 누가 주나?** 서버가 페이지 번호까지 태그해주면 우리는 정렬+크롭만. 안 주면 우리가 페이지번호 OCR로 식별.
- **쎈 답공간 크기·일관성** — 문제 밑 답 공간이 등록 가능한 형태인지 실제 페이지로 확인 필요.

## 6. 현재 상태

| | 상태 |
|---|---|
| 인식기 (YOLO-det, 합성학습) | ✅ 동작 (마이너스/필체 개선 진행) |
| 자체 시험지 앞단 (마커+크롭) | ⬜ 미구현 |
| 쎈 앞단 (등록+인식+정렬) | ⬜ 미구현 |
| 넘김/장분리 | — 다른 서버 |
